One shared procedure for every project

Approved October 5, 2026. Use current canonical records before acting.

Start with the current project

  1. Read the current Vault policy and project home; load project-work context.
  2. Respect active claims. Work in an isolated branch from the approved revision and acquire a claim.
  3. Keep changes scoped. Test and review the final revision.

Finish the update everywhere

  1. Publish the reviewed code branch to the registered GitHub repository.
  2. Finish the exact revision. Submitted means awaiting canonical promotion.
  3. On BEAST, update the tracker, registry, project home, progress and next action; commit and publish scoped Vault changes.
  4. Publish the Mission Control Vault snapshot and verify its source revision.
  5. Before deployment, use the release guard. Verify the live result and record the deployed revision.

Keep the two project HTMLs current

Every project folder has where-everything-is.html and Shared_Worker_Project_Plan.html. Open the project home for current locations, accounts, progress and blockers. Run the strict location and project-home checks before accepting a handoff.

Missing folders, outdated pages or unavailable sync remain pending. Do not label a partial check complete. Preserve existing details and record honest unknowns.

Protect the source of truth

GitHub holds code; private business data and backups stay in private storage. BEAST writes canonical Vault records; other machines submit results. Do not bypass hook trust, claims or permissions.
