Facebook & Instagram setup

This page is for the administrator configuring Matt’s CRM. Matt can use research and assistant tasks while account setup is pending. No social metrics are available until an account is connected.

Configure the Meta app

  1. Create a Meta developer app for Matt’s business with Facebook Login for Page access and Instagram business login. Confirm verification, app review and advanced access requirements in the dashboard. Development-mode access can be restricted to app roles.
  2. Keep the CRM’s existing Cloudflare Access protection. Register these exact authorized callbacks:

    Facebook: https://matt-realty-desk-demo.jstone6784.workers.dev/api/social/callback

    Instagram: https://matt-realty-desk-demo.jstone6784.workers.dev/api/social/instagram/callback

  3. Facebook requests only pages_show_list and pages_read_engagement. Instagram uses its separate login with only instagram_business_basic. No publishing, messaging, comment-management or pages_read_user_content permission is requested.
  4. Matt must have access to the chosen Facebook Page. Instagram must be a professional Business or Creator account; it does not have to be linked to the Facebook Page. Connect each account separately.

Configure Cloudflare securely

Set these on the existing CRM Worker. Use your approved secret manager or Cloudflare’s secret inputs. Never paste secret values into this page, chat, Git, or a task.

META_APP_ID
Facebook login app identifier.
META_APP_SECRET
Facebook app secret; store as a Worker secret.
IG_APP_ID
Instagram app identifier from the Instagram API setup.
IG_APP_SECRET
Instagram app secret; store as a Worker secret.
SOCIAL_TOKEN_KEY
Base64 encoding of 32 cryptographically random bytes; store as a Worker secret. This encrypts retained account credentials. Keep the key safely; rotation requires reconnecting accounts.
META_REDIRECT_URI
The exact Facebook HTTPS callback above, without extra query parameters.
IG_REDIRECT_URI
The exact Instagram HTTPS callback above, without extra query parameters.
META_GRAPH_VERSION
A supported Graph API version. The implementation defaults to v25.0; validate the configured version and permissions before enabling connections.

Connect and verify

  1. Return to Audience. Each connection button becomes available once its required settings are valid.
  2. Matt approves Facebook access, then chooses the Page in the CRM. He separately approves the professional account at Instagram. The code exchanges tokens server-side; retained credentials never appear in the browser.
  3. Choose Fetch latest engagement. Check the account names, fetched date, available counts and any partial-data warning. An unavailable measurement is not zero.
  4. If access is revoked or expires, reconnect. Disconnect removes local credentials and pending approvals while retaining saved reports. To revoke app grants too, remove the app in Meta’s business integrations and Instagram’s connected apps.

Backups and privacy

The additive database migrations are 0003-social.sql and 0004-command-center.sql. Apply them through the reviewed release procedure before enabling the new Worker. Portable backups include saved research, jobs and nonsecret snapshots; they intentionally exclude encrypted access credentials and OAuth sessions. After restoration, reconnect accounts. Reports cover a bounded sample of recent posts, not a complete historical analytics export. Engagement never creates CRM contacts or marketing permission.
